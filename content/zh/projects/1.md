> 客户在 4S 店里拒绝智能化吗？恰恰相反——他们是带着“想相信”的心情走进展厅的。真正的问题是：一台车的核心卖点越集中在智能座舱和辅助驾驶上，静态展车就越无力证明它们。客户能摸到的只有皮质和漆面，值几十万的那些能力，要开起来才“活”。这个项目要解决的，就是这个“卖得最贵的东西，恰恰看不见摸不着”的矛盾。

## 背景

很多车企的展车模式已经形成自己的特色，但部分合资车企仍未找准切入点，店端的车辆展示存在明显短板，核心问题聚焦于**数字化、智能化及科技化配置的体验传达不足**：展车未能通过直观、可交互的方式呈现产品核心科技亮点，客户难以快速感知其智能优势，不仅直接影响线下看车的体验与满意度，也使其与新势力品牌、主流新能源车型的差距持续拉大。竞品普遍以场景化、沉浸式的科技体验打动消费者。

## 挑战

**多维度需求融合与趋势适配**：需收集销售系统端、店端对“展车模式”的实际诉求（如展示效率、操作便捷性、落地可行性），同时对标行业领先趋势，平衡“需求实用性”与“体验领先性”，避免策略脱节实际或落后于竞品。

**体验价值与品牌认同深化**：需通过展车体验优化同时做到三件事：提升客户对静态展示的满意度，强化产品科技化属性的感知，加深品牌“科技、智能”的标签印象，最终缩小与新势力品牌、新能源车型的体验差距，增强客户对品牌的情感认同与选择倾向。

**静态展示体验升级**：现有展车以传统静态陈列为主，缺乏针对数字化、智能化配置的互动设计，客户难以通过静态场景直观感知产品科技亮点。需突破“仅看外观、摸内饰”的模式，把动态交互融入静态展示，让科技配置在静态场景中可触、可感、可体验。

## 行业趋势

传统展车以静态空间与造型展示为主，当前品牌展车则开始更主动地呈现产品核心价值与使用场景，展车体验从“感知外观属性”延伸到“理解产品能力与使用方式”。在这一转变下，各品牌的展车体验差距不再主要来自硬件造型，而是集中在数字化功能的丰富程度与可感知性，以及座舱系统的沉浸式交互体验水平。

## 走访4S店

本次调研对 4S 店潜在用户的看车过程做了实地走访，目标：

**捕捉用户行为、收集专业见解、洞察体验核心、提炼典型旅程与痛点。**

![](https://shangqing.site/images/blogs/1/2e733980-5347-8152-95c2-c8340ec6e0ba.webp)

## 核心洞察

走访与销售系统端的访谈汇总下来，六个问题反复出现：价格与优惠不透明，信任难建立；配置信息更新慢，客户转头去第三方平台查；座舱智能功能停留在配置表上，静态展示时因账号、车机、电源限制无法实际体验；试驾时间短、路况不可控；静态体验只停留在空间与外观；智驾功能客户基本没有认知。

> 这六条不是六个孤立的坑。放在一起看，它们有共同的根源：**展车只承载了“看”的功能，没有承载“验证”的功能。**客户对智能化的决策需要证据——价格要能算清、配置要能查到、座舱要能坐进去操作。传统展车把验证环节全部外包给了销售话术和客户的想象，而新能源时代的购买决策，恰恰最依赖亲手验证。

其中两个洞察，直接决定了后面的设计取舍。

### 洞察一：验证成本才是第一瓶颈

数字化功能的价值是动态的，但展厅只给静态窗口。客户与智能座舱的接触窗口只有看车的二三十分钟，而这些功能是为驾驶场景设计的。更致命的是，演示链路上任何一分钟的技术摩擦——登录账号、找电源、等车机启动——杀死的不止这一分钟，而是客户对整块“智能化价值”的信任：连演示都跑不顺的车，他不敢想象它跑在路上是什么样。所以设计上的结论是：**把一次智能体验的获取成本压到接近零，比增加十个功能点更有价值。**行业后来的通行做法（展厅预置演示模式、一键场景剧本）也印证了这个方向。

### 洞察二：设计对象不只是客户，还有销售

客户体验设计得再好，落地执行者是销售，而销售的行为由考核驱动——留资率、成交周期。任何拉长讲解时间的“好体验”，都会被他悄悄绕过。我们在收集店端诉求时发现，销售自己也要花大量时间向客户解释同一批配置问题。这让我们把方案定位成一件双边的工具：**对客户是一台会自己讲故事的展车，对销售是一个省话术、新人快速上手的演示系统。**只做前者，方案活不过试点。

HMW QUESTIONS：我们如何通过为用户提供沉浸式与场景化的静态展示，增强客户与店端的信任关系，传达品牌智能互联/操控性能的体验价值？

![](https://shangqing.site/images/blogs/1/2e733980-5347-8148-9141-dffb877cccd2.webp)

## 体验策略

| **洞察** | **策略** |
| ---------- | ---------- |
| 客户与销售的信任关系建立难 | 以透明的价格、专业的讲解和有温度的沟通，重建客户与销售的信任 |
| 配置与价格信息传达低效 | 把配置与价格信息分层讲清、可视化呈现，并支持客户动手查询比较 |
| 数字化座舱感知弱 | 让客户在场景中以沉浸方式体验座舱，并支持按个人偏好设置 |
| 试驾浅尝辄止 | 覆盖更多场景、按客户需求定制内容，留出足够时间做深度体验 |
| 静态体验保守沉闷 | 在静态展车中加入互动、场景与主题元素，改变“只看不动”的沉闷 |
| 智驾功能认知 / 接受度低 | 由浅入深地普及智驾功能，配合可视化演示和实际场景讲解 |

表格背后是一条统一的取舍线：每一条策略都在回答“如何让客户自己动手验证”，而不是“如何替客户总结卖点”。信息类问题（价格、配置）交给可查询、可带走的透明工具；体验类问题（座舱、智驾、静态氛围）交给零门槛的场景演示——原则是**让证据出现在客户手里，而不是出现在销售嘴边**。

> 用户视角原则：所有体验设计均以用户需求为核心，避免“技术导向”，用用户易懂的语言、可感知的场景传递产品价值。

## 设计落地

这是一个从调研、洞察、策略到设计交付全程跟进的团队项目，我作为体验设计师参与了完整链路：实地走访与店端访谈、洞察框架的搭建、策略到交互方案的转化，以及向销售系统端的落地对齐。方案完成设计交付后，我在产品实际上线前离开了公司，所以下面只写我确信的两点，不复述上线结果。

对“验证成本”的判断，是项目里最有价值的决策。中期我们曾纠结于展示功能的完整度——把车机的能力全部搬进展台，还是只挑场景做深。最终选择后者的依据，就是走访中看到的那些被登录和等待打断的瞬间。事后看，这个取舍也符合行业演进的方向：静态展车的体验竞争，比的从来不是谁的功能列表长，而是谁让客户更早地“亲手确认”。

对销售角色的重新定义，改变了方案的形态。把销售从“讲解员”变成“演示系统的受益者”，是这套方案能被店端接受的关键。

> 体验设计在 B 端渠道里落地时，执行者首先是用户——这是这个项目给我上的最重要的一课。
