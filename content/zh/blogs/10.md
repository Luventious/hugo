## 一、先把结论说在前面

UX 设计师在整车研发中的能力边界：**在需求冻结、设计冻结、数据发布、SOP 这四个不可逆节点之前，把一句"用户想要更贴心的座舱"这样的模糊需求，翻译成工程能排期、供应商能交付、验收能打分的目标，并在冻结那天守住它。**

整车 UX 有个绕不开的事实：用户能感知到的体验，90% 在 SOP 前两年就被决定了，而真正能验证它对错的时间窗口，只有需求冻结前的那几个月。过了这个窗口，只剩补救，谈不上设计。

## 二、为什么通用 UX 流程在这里失效

互联网产品可以灰度、A/B 测试、快速迭代，错了下周改回来。整车不行，原因有三：

* **周期长**：2–5 年。立项时定义的用户，量产时可能已经换了生活方式；体验目标如果不锁死，一定会在漫长链条里被稀释成一句口号。

* **不可逆**：硬件、模具、E/E 架构一旦冻结，改动成本指数级上升。一个 HMI 逻辑的调整，可能牵扯控制器算力、供应商合同和法规验证。

* **强耦合**：一个"体验目标"背后往往站着五六个部门和 Tier1 供应商。有人掉链子，体验就走形。

Figma、用户访谈、A/B 测试解决的是表达和局部验证，解决不了跨部门、跨年度地锁定并验收一个体验目标。整车 UX 真正需要的，是一套能把目标写进流程、在冻结前锁死、在交付时验收的机制。

## 三、能力边界：主导什么，影响什么，不碰什么

把能力边界落到权责上，就是一张表：按节点话语权划分，冻结前 UX 主导，冻结后只剩影响。

| 层级 | 内容 | 说明 |
| ---------- | ---------- | ---------- |
| **UX 主导** | 用户洞察、场景定义、体验策略（价值主张 / 体验原则 / 体验价值点）、体验验收标准 | 这些必须由 UX 拍板，不能交给工程或市场代劳 |
| **UX 影响** | 功能清单优先级、HMI 方案、性能目标设定、供应商交付验收 | 你不一定有决定权，但必须在场、必须留痕、必须能否决明显走偏的方案 |
| **UX 不碰（但需理解）** | E/E 架构、硬件选型、成本核算、法规认证 | 不需要动手，但要知道它们如何反过来限制体验目标 |

## 四、双线咬合：四个节点上 UX 该做什么

整车开发和体验工作并行推进，在四个不可逆节点上咬合。

### 节点一：需求冻结前 —— 把体验写进特征目录

* **UX 动作**：从场景库出发，定义价值主张与体验原则，拆解到用户可感知、内部可实现的体验价值点，再映射到功能清单。

* **核心产出**：体验策略树、场景—功能映射表、写入特征目录的体验目标。

* **话语权**：这是整个流程中 UX 话语权最大的时刻。

### 节点二：设计冻结前 —— 锁定关键体验目标

* **UX 动作**：对关键体验目标做最后一次评审，明确此后每个变更都要过体验 gate。

* **核心产出**：体验目标清单及验收口径、变更评审机制。

* **话语权**：从主导转向共同决策，需要和管理层、工程、采购谈判。

### 节点三：数据发布 —— 用体验验收放行，而非仅工程达标

* **UX 动作**：以用户为中心的验收体系参与放行，工程达标只是及格线，不是终点。

* **核心产出**：体验验收报告、问题清单及闭环计划。

* **话语权**：强建议甚至一票否决。

### 节点四：SOP 后 —— OTA 与真实数据回灌

* **UX 动作**：用真实使用数据验证当初的体验假设，把结论输入下一代产品定义。

* **核心产出**：体验假设验证报告、下一代车型输入。

* **话语权**：影响下一代，不再影响当前代。

## 五、复盘：体验目标是怎么走形的

体验目标走形通常有三条路径：

1. **策略传递断层**：价值主张停留在 PPT，没有翻译成特征目录，到了工程侧就各说各话。下次：每个价值点必须落到可验收的体验目标。

1. **冻结前没锁定**：以为"后面还能改"，结果硬件已定、预算已锁。下次：把冻结节点当成硬闸门，过闸前必须签字。

1. **供应商交付不可验收**：体验目标没写进合同和验收标准，交付什么样就是什么样。下次：体验目标进入供应商交付物清单。

## 六、闭环：体验目标如何连到"爆款"

爆款不是功能堆出来的，是用户价值被准确命中。体验策略树把品牌定位、价值主张、体验原则一路串到功能特性，让整辆车在体验层面有整体性，而不是一堆各自为政的亮点。

可度量的体验目标，让"体验好"从口号变成可验证的断言；OTA 数据回灌，让下一代产品定义建立在真实反馈而不是猜测之上。

## 附录：P-I-E 三阶段流程速查

| 阶段 | 目标 | 子步骤 | 关键活动 | 工具/方法 | 输出物 |
| ---------- | ---------- | ---------- | ---------- | ---------- | ---------- |
| **1. 产品企划阶段（Planning）** | 定义问题、收集需求，建立基础蓝图 | 1.1 用户研究 / 1.2 市场分析 / 1.3 价值定义 / 1.4 需求定义 | 访谈用户、调研 NEV 车主痛点；分析竞争对手；优先级排序用户需求；评估技术可行性 | 用户访谈/问卷、SWOT 分析、用户画像、PESTEL 分析 | 用户需求报告、产品路线图、需求规格书 |
| **2. 创意阶段（Ideation）** | 生成创新想法，设计初步方案 | 2.1 脑暴与 idea 生成 / 2.2 概念设计 / 2.3 原型构建 / 2.4 内部评审 | 跨团队脑暴；绘制草图或数字模型；快速构建低保真原型；反馈迭代初步想法 | 脑暴工具、设计软件、故事板、SCAMPER 方法 | 概念草图/模型、低保真原型、创意方案集 |
| **3. 评价阶段（Evaluation）** | 验证方案、收集反馈、推动迭代 | 3.1 用户测评 / 3.2 数据分析 / 3.3 迭代优化 / 3.4 最终验证 | 模拟测试；分析使用数据；根据反馈调整设计；A/B 测试最终版本 | 用户测试工具、量化指标、热图分析、焦点小组 | 测试报告、优化建议、最终 UX 设计文档 |
